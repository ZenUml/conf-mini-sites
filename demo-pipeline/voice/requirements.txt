# Pinned Python dependencies for demo-pipeline/voice/kokoro.py (design doc, "Dependencies": "A project-local
# Python virtual environment for pinned Kokoro and audio dependencies. The PoC uses an English preset voice
# and does not clone a person's voice").
#
# This is the full transitive closure actually installed (`pip freeze`), not just the two top-level packages
# (kokoro, soundfile) — pinning only the top level would let misaki/torch/spacy/transformers/etc. float on a
# fresh install, defeating the point of "pin exact versions you actually install". `en_core_web_sm` is
# included explicitly too: without it pinned here, `KPipeline(lang_code='a')`'s first call triggers spaCy's
# own `pip install` of that model as a side effect (observed during Task 4's runtime gate) — pinning it here
# makes `pip install -r requirements.txt` alone fully reproducible, with no further network calls triggered
# from inside kokoro.py itself.
#
# Regenerate with: demo-pipeline/.venv/bin/pip freeze | sort
#
# Platform notes (verified 2026-07-21, macOS 25.5.0 arm64):
#   - Requires Python >=3.10,<3.13 (kokoro/misaki do not yet support 3.13 — the system `python3` on this
#     machine is 3.13.5, so the venv must be created with `python3.12 -m venv demo-pipeline/.venv`, not
#     plain `python3`).
#   - `torch==2.13.0` here is the plain macOS arm64 wheel (no CUDA build exists for macOS, so there is no
#     separate "CPU-only" index URL to opt into on this platform, unlike Linux/Windows) — CPU/MPS inference
#     only, no extra flags needed.
#   - No system packages (e.g. espeak-ng) are required for the English voice path: misaki's `[en]` extra uses
#     `espeakng-loader` (a bundled, pip-installed espeak-ng binary) and `phonemizer-fork`, not a system-wide
#     espeak-ng install.
