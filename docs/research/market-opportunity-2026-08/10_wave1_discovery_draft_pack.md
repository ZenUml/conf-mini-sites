## Learning objective

The first wave should test, not promote, the repositioned artifact hypothesis:

1. What real file or build output exists: one HTML file, a local folder, externally hosted assets, or unbuilt JSX?
2. What named workflow triggers it, who views it, and how often does it recur?
3. Does Confluence placement beat the current alternative for an explicit reason?
4. What fails under current limits: input shape, outbound network, viewer size, local state, admin approval, or price?

The set intentionally mixes likely fits with a classification-boundary case. Evidence IDs are discovery leads, not permission to contact.

## Interview capture template for T07 preparation

For each future authorized conversation, capture facts before interpretation:

- Candidate ID and evidence ID
- Interview date and channel
- Creator, viewer, admin, and buyer roles
- Trigger and named workflow
- Recurrence: observed last three cycles, not intended cadence only

- Network, authentication, storage, host-DOM, and write-back requirements
- Current workaround and why it is insufficient
- Admin/security/procurement path
- Successful publish outcome, if tested
- Why Confluence is preferred or not preferred
- Price comparison and threshold, only if the T13 script is used
- Counterevidence and fit classification
- Permission for any follow-up or artifact retention

Do not convert “agreed to talk,” “opened a demo,” or “shared a file” into product success. The target outcomes remain artifact publication, named-viewer use, and a repeated real workflow.
