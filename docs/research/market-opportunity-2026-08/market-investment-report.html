Market decision / evidence cut 2026-08-02

需求是真的。
当前入口错了。

市场确实需要把互动 HTML 工作成果放进 Confluence；但近期证据更偏向单文件、粘贴式 AI 报告、原型和本地工具，而不是当前产品要求的多文件文件夹。

01
Observation / 已观察

市场成立，但“多文件”不是当前最强购买理由。

证据支持一个宽类别，也暴露了当前产品契约与近期创作方式之间的断层。

What is real

真实需求集中在工作成果，而非 HTML 技术本身。

  • AI 生成的互动报告、部件和决策工具需要被团队打开。
  • QA、技术和客户报告需要比 PDF 更好的导航与交互。
  • 原型、训练模拟器和离线图表需要留在讨论发生的页面。
  • 隐私、可发现性和稳定更新是横向证明，不是独立获客切口。

EVIDENCE / E075 · E083 · E085 · E089 · E093 · E119

What it means

应卖“互动工作成果”，而不是“另一个 HTML 宏”。

  • 通用 HTML 宏已有成熟付费与免费替代品。
  • 外部 artifact host 已把“一文件一链接”做成默认体验。
  • Confluence 页面上下文与隔离边界才是潜在差异。
  • 如果输入仍拒绝单文件，最强 SEO 意图无法诚实承接。

Recommendation / 投入模型

每项开发，都要解锁一个可兑现的搜索承诺。

SEO 与开发不是两个 backlog。橙色依赖线决定某个页面何时能从“研究意图”变成“产品承诺”。

  • 明确文件、URL、snippet、folder 的选择路径

SEO investment

先占“如何选择”，再占“结果是什么”。

当前就能建设诚实的选择与信任页面；AI、报告和用例页面要等对应能力与 fixture 通过。

ID搜索任务 / 页面现在的动作发布门槛
P01embed HTML in Confluence Cloud刷新现有支柱：snippet / URL / file / folder 四路选择器现在刷新，避免再造一个相互蚕食的 HTML macro 页面。每条路径都有可运行示例；错误路径诚实推荐原生 iframe、竞品或 Forge。
S14HTML sandbox / security in Confluence信任与限制页现在建设；同时服务管理员审查和减少错配安装。CSP、秘密扫描、页面上下文与不支持能力描述必须和当前行为一致。

P02share AI-generated HTML in ConfluenceAI 互动工作成果支柱现在准备内容与示例，不发布“可上传单文件”承诺。单文件支持；至少 5 个 artifact，4 个无需改源码发布。

S03embed a single HTML file高交易意图兼容页面功能完成前不发布为产品页。一文件 E2E、大小上限、复杂模拟器和明确错误。

S06–10Allure · Plotly · prototype · simulator · client report结果型支持集群只做 artifact 能力已经通过的子集。每页一个真实 fixture、披露输入与边界、一个结果型 CTA。
S16Confluence HTML height / large view排错与产品证明在安全大视图行为确定后发布。桌面/移动截图、无 resize loop、键盘可达。

04
Product investment

先修激活契约，不先堆协作功能。

最小开发组合要让近期 artifact 进得来、看得清、错得明白，并能把成功归因到真实用户。

优先级任务为什么现在做最低验收
P0 / T01接受单一根目录 index.html近期 AI 与报告证据频繁是单文件；当前 validator 明确拒绝。一文件与文件夹都通过单元/E2E；限制、秘密扫描和 CSP 不退化。
P0 / T03兼容性契约与可操作错误复杂单文件在竞品中已有不透明失败；错误本身会阻断激活与内容可信度。结构、大小、秘密、网络和不支持输入都说明原因与下一步。
P0 / T02一文件选择器或 paste-first竞争品和用户语言都偏向粘贴/一文件；但入口决策应服从 T01 契约。创作者不添加虚假资源即可从输入到预览；无歧义的文件/代码路径。
P0 / T04安全大视图与尺寸策略当前 360px 固定框会削弱报告、原型和模拟器；无上限自动高度又会产生循环风险。5 套 canonical fixture 在桌面/移动可用；大视图键盘可达；无无限增长。
P0 / T05三套证明 fixtureSEO 与定位必须展示结果，不是类别声明。报告、原型、模拟器均无外网；披露文件形态、本地状态和限制。
P0 / T09可归因的生产激活当前信号不足以区分创作者、测试与 API 流量；没有可靠归因就无法判断 SEO。环境与来源标记完整；生产漏斗排除内部/E2E/CI；记录真实 republish。
P1 / T10CI/API publisher discovery更新自动化有需求，但当前 UI fit 和周期性证据不足。3 位每周更新者，2 位愿意运行受限原型，再进入建设。
P1 / T11版本、回滚与评论 discovery外部 artifact host 在竞争；但尚未证明是 Mini Sites 的当前核心失败。5 位周期报告作者中至少 3 位有近期错版本或评审上下文问题。

不放宽 CSP 追 live dashboard

实时 API、认证资产和共享写回属于另一套产品与威胁模型；当前需求应路由给专用工具。

不先做版本系统

今天可诚实主张稳定覆盖同一位置；只有真实评审失败通过门槛后才投资版本与评论。

不先做通用部署平台

Cloudflare Pages、GitHub Pages、Tiiny 等已经成熟；Mini Sites 的理由必须是 Confluence 上下文。

05
Conditional sequence

90 天不是发布日历，而是证据解锁顺序。

上一阶段没有通过门槛，下一阶段就不扩大。每个阶段都同时包含 Build、Grow 与验证。

0–30 天

  • 确定单文件契约并完成 T01/T03。
  • 选择 T02 输入方式；原型安全大视图。
  • 刷新 P01，准备 S14；所有文案只描述当前能力。
  • 取得明确授权后，从候选队列收集真实 artifact。
  • 定义 UI/E2E/CI/API 的归因字段与成功事件。

31–60 天

  • 用 10 个真实 artifact 跑兼容矩阵。
  • 完成报告、原型、模拟器三套 fixture。
  • 在桌面和手机完成大视图验收。
  • 只有通过能力门槛后，发布 P02/P03/S03。
  • 记录发布、命名观众使用和真实重复周期。

61–90 天

  • 扩展同时满足 artifact fit 与搜索意图的支持集群。
  • 用归因漏斗评估 SEO，而不是用流量代替结果。
  • 只有整体 wedge 门槛通过，才申请 Marketplace 定位测试。
  • 只有复发门槛通过，才进入 CI、版本或评论建设。
  • 根据证据重新分配 55/25/20 初始投入。

授权边界：本序列是研究建议。外联、Marketplace 文案/价格、生产资源、部署和产品实现仍需要各自明确授权。

06
Decision gates

继续、保留或暂停，都要有可证伪条件。

不是“页面上线了就成功”，而是用户带着真实成果穿过了完整工作流。

Proceed / 重定位切口

六个数字必须同时成立

  1. 5 位当前 Confluence Cloud 创作者提供真实 artifact。
  2. 4 个无需修改源码即可发布。
  3. 3 个命名工作流每月或更频繁。
  4. 3 位明确偏好 Confluence 结果，并说明理由。
  5. 2 位管理员接受托管、隔离和权限故事。
  6. 2 次价格对话形成可信比较或阈值。
Retain / 多文件切口

只有现实文件夹复发才保留

  • 5 个当前 Cloud 团队展示真实文件夹。
  • 3 个每月或更频繁更新。
  • 2 个无需开发者帮助完成发布。
  • 2 位管理员接受付费路径。
Pause / 收窄

两条暂停线

  • 少于 3 次访谈出现重复、兼容的工作。
  • 8 次 walkthrough 中至少 5 次原生或免费替代品已经足够好。
07
Anti-positioning

明确不做什么，会让窄承诺更可信。

错配流量应该被路由，而不是被转化。以下工作真实存在，但不属于当前 Mini Sites。

NOT / LIVE BI

不是实时 BI 或运营 dashboard connector

需要认证、刷新、外部 API 或 drill-down 时，用 Tableau、Grafana、Jira/report app 或合适的已托管 iframe。

NOT / HOST DOM

不是 Confluence 页面注入器

隔离内容不能读取宿主页面 DOM、全局任务状态或组织级上下文；需要这些能力时应构建 Forge app。

NOT / BACKEND

不是秘密、数据库或写回平台

不承诺服务器秘密、认证外部调用、共享数据库、多用户持久化或向 Confluence 写回。

NOT / URL HOST

不是已托管 URL 的默认答案

目标已经有稳定、可 frame 的 URL 时，Confluence 原生 iFrame 通常更直接且免费。

NOT / LIVE DESIGN

不是 live Figma / Blueprint 集成

需要实时 source of truth 时，用 Smart Links 或专用集成；Mini Sites 只考虑与工具无关的静态导出。

NOT / GENERIC MACRO

暂时不是最好的单文件 HTML 宏

在单文件支持完成前，OST、Narva、Appfire 或 Yamuno 的输入路径更简单；不要用未来能力竞争今天的搜索。

研究口径与限制

观察：公开帖子、评论、issues 和文档可以证明具体问题、artifact 与结果；不能直接估算 TAM、付费客户数或意愿。

为何 SEO 不能先于功能

最强近期需求经常是单文件或粘贴式；当前 validator 明确要求多于一个文件。固定 360px viewer 又会削弱报告与原型的完成体验。因此 P02、P03、S03 等高价值页面必须等能力和 fixture 通过，避免页面吸引到产品必然拒绝的用户。
